# V1: autonomous writing, verification, and measurement

V1 makes Writer capable of producing a complete technical article and
makes the result experimentally measurable. All Prime mechanisms are
reused, not reimplemented; everything new is additive.

## /write (capability orchestrator, not pipeline)

`writer/prompts/write.md` exposes capabilities — brief, angles, research,
sources, drafts, alternates, extraction, verification, criticism,
comparison, revision, revert, final selection — and requires the model to
decide what the piece needs. Run boundaries use
`trace_begin`/`trace_finish(quality=trace_summary())`. Verified live only
as far as credentials allow (see "Not run live").

## Claims: extract → verify (evidence-gated)

- `extract` (`pa-writer/src/extract.rs`, `writer/_extract.py`): sentence
  splitting + keyword signals → `ClaimType`/importance candidates with
  `draft §N` locations. Heuristic on purpose; the ledger decides.
  Fixed live during dogfood: glued digit+units (`1500ms`) and the
  `teams`/`ms` substring false positive.
- `claims::verify` / `claims_verify`: `verified` without source ids or an
  exec ref is refused — no declaring truth by memory. Notes record what
  was consulted. `update` remains for triage transitions.
- `verify_draft`: high-importance-unverified-first queue.

## Executable checks

`writer.exec_check` runs commands in the kernel sandbox (Prime's trust
posture: user permissions, not a sandbox boundary), persists
`traces/exec.jsonl` records, optionally links `exec_ref` to a claim.
Failures are data. Dogfood use: AST-checked the article's `rlm.spawn`
fence against the real runtime source.

## Critic subagents + model diversity

`editorial-critique` skill now carries the spawn recipe: diagnose with a
ranked-issues + preserve-list + smallest-fix contract, return findings via
`collect`, never persist drafts; the writer repairs as a new revision.
`models.json` policy (`writer:inherit`, `critic:different-family-if-available`,
`verification:reasoning`); family is the opaque provider segment of
`provider/model-id` selectors from `rlm.find_models` — no vendor names.
Diversity is preferred, never mandatory (single-model environments work).

## Benchmarks + blind comparison

`benchmarks/technical-writing/`: 11 tasks (explainer, tutorial,
architecture, argument, product-education, comparison, editing,
shortening, complex-concept, thesis, jev-explainer), each with brief/audience/
constraints/sources/hard requirements. `run.py run --task T --arm
vanilla|writer --model SELECTOR` isolates harness effect (same selector
both arms; writer arm = expanded `/write` + Writer skills); `blind` seals
provenance to `evals/blind.jsonl`, `resolve` maps frame winners back to
arm labels, `tally` counts wins. Six standard criteria, no scores.

## Limitations (honest)

- No live-model runs: no credentials/daemon in this environment, so
  `/write` autonomy, critic subagents, and same-model vanilla-vs-Writer A/B
  are built + plumbing-verified (real binary accepts every flag `run.py`
  passes) but not executed. The dogfood judge was the author, who could
  infer provenance from content — machinery correct, blindness weak.
- Extraction recall is modest (4 candidates on draft-001 pre-fix);
  model review added 3 claims manually. No `update-claim-type` API:
  misclassified candidates keep their type (documented in notes instead).
- RLM-blog source informed framing but has no inline citation in the
  article; citation practice is still manual.
- Critiques persist under `traces/critiques/` (new path); no Rust reader
  yet (readers ignore extra files).
- Tokens/cost absent from quality: merging Prime tracing figures is
  documented but unwired.
