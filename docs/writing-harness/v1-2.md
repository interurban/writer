# Writing harness evaluation — V1.2

V1.2 changes no writing behavior. `/write`, framing, technical-writing,
critic, verification, density rules, and the task briefs are frozen for the
duration of an experiment; V1.2 only makes the *measurement* trustworthy
enough to believe (or disbelieve) the result.

## Why

The Jev dogfood run produced one judgment that declared a winner while its
own reasoning described the other article. Nothing in the harness caught it,
so the number could have been reported as a Writer win. V1.2 makes a
judgment earn its place: it must quote the article it claims is better.

## The evidence rule

Every verdict — model or human — must carry a verbatim `evidence` span of
12-400 characters copied from the article judged better (for a tie, from
either article). Validation against the raw candidate text is
**authoritative**:

| Situation | Outcome |
| --- | --- |
| span found verbatim in the winning article | valid |
| span found after whitespace normalization | valid, plus an `evidence matched only after whitespace normalization` warning |
| span found only in the losing article | invalid |
| span found in neither article | invalid |
| span missing, or under 12 / over 400 chars | invalid |

A reasoning/winner contradiction is a **warning only**. It never discards a
validated verdict and never repairs identity — it is surfaced in
`report.md`, in `export.csv`, and in `judgments.jsonl`.

## Retries

An invalid first verdict gets exactly one retry (`MAX_JUDGE_ATTEMPTS = 2`).
The retry uses a distinct seed and therefore a freshly randomized A/B order
and a new sealed frame. Both attempts are persisted in the record's
`attempts` list. A second invalid verdict stays invalid:

- no forced winner,
- no silent identity repair,
- no conversion to a tie.

Invalid comparisons are excluded from win counts and listed in
`report.md` under "Invalid comparisons", with the reason and attempt count.

Frame ids are never reused (`_unique_frame_id`), so re-judging a comparison
cannot collide with a stale sealed mapping.

## Run the experiment

```sh
# 0. readiness: never spend 66 generations on a model that will not answer
python3 benchmarks/technical-writing/run.py check-models \
    --model <author-selector> --judge-model <judge-selector>

# 1. author phase (11 tasks x 2 arms x 3 runs = 66 outputs)
python3 benchmarks/technical-writing/run.py experiment \
    --model <author-selector> --judge-model <judge-selector> \
    --thinking medium --runs 3

# 2. judging (33 pairs x 7 dimensions = 231 comparisons)
python3 benchmarks/technical-writing/run.py judge --experiment <exp-id> \
    --judge-model <judge-selector>

# 3. report
python3 benchmarks/technical-writing/run.py summarize --experiment <exp-id>
```

`check-models` probes every configured selector with the cheapest possible
round trip and exits non-zero unless all of them answer, so an auth or model
failure surfaces before the expensive phase instead of after it.

Author and judge models are independent (`--model` / `--judge-model`).
Family is the provider segment of the selector and nothing else — Prime does
not expose model families reliably, so `author_family` / `judge_family` are
`null` rather than guessed. A judge from the same family as the author is
flagged on every affected record and in the report header.

## Reproducibility

Each experiment directory carries:

- `manifest.json` — models, seeds, task input hashes, harness hashes,
  `behavior_version`, and tree state (`git_commit`, `git_dirty`,
  `git_diff_sha256`).
- `behavior.md` — the human-readable freeze: what each arm received, every
  behavior-defining file hash (prompt templates, the six skills, the
  framing skill, `pa-writer/src/framing.rs`, `_framing.py`), and the task
  input hashes.
- `runs/<task>/<arm>/run-<k>/` — `prompt.md`, `command.txt`, `events.jsonl`,
  `stderr.txt`, `output.md`, `meta.json`, `economics.json`.
- `judge-state/evals/blind.jsonl` — the sealed A/B mappings.
- `judgments/model/.../<dim>.json` — per-comparison records with all
  attempts.
- `judgments.jsonl` — one row per attempt, valid and rejected alike.
- `export.csv` (per judgment), `economics.csv` (per run), `report.md`.

`behavior_version` is the digest of the behavior-defining file hashes, so
two reports can be compared even when the git commit is unusable. If the
tree is dirty at run time, `report.md` and `behavior.md` both say so: the
commit does not describe the behavior that produced the numbers. Commit the
freeze before the live run to remove the caveat.

## Economics

Token and cost totals come from Prime's `message_end` usage objects, with a
session-file fallback; `turn_end` / `agent_end` repeats are excluded so
nothing is double counted. Missing metrics stay `null` — never zero, never
estimated. Writer-side ledger metrics (`sources`, `claims_*`, `drafts`,
`revisions`, `comparisons`, `exec_checks`, `framings_proposed`,
`framing_selected`, `framing_components`) are honestly `null` for the
vanilla arm, which has no ledger.

## Human judging

`human-judge` follows the same evidence contract: A/B/tie/`skip`, then a
required verbatim span, validated before the identity is unsealed. An
unvalidatable span is re-asked once, then recorded as invalid with no
winner. `skip` is an explicit abstention and is never stored as a tie.
Labels are revealed only after a pair is fully submitted and persisted.

## Agreement

When a model judge and a human judged the same `(task, pair, dimension)`,
`report.md` prints agreement per dimension. Dimensions with no overlap are
omitted rather than reported as 0% — a missing comparison is not a
disagreement.

## Validation without models

```sh
python3 benchmarks/technical-writing/run.py selftest
```

Covers blind resolution under both parities, evidence acceptance and
rejection (including re-wrapped quotes and quotes from the losing article),
contradiction warnings, retry-then-valid, invalid-after-retry, identity
resolution across both A/B parities, JSONL retention of rejected attempts,
agreement counting, manifest/behavior capture, telemetry parsing, length
targets, per-comparison seeds, and the vanilla `null` ledger asymmetry.
