# Task: explainer — Why MCP matters

## Brief

Explain why the Model Context Protocol matters to experienced developers
who have built one-off tool integrations. About 1,200–1,800 words.

## Audience

Senior backend engineers. They understand APIs, auth, SDK versioning, and
the cost of bespoke glue code. They have not used MCP.

## Constraints

- Concrete over generic: name the mechanism (hosts, clients, servers;
  tools, resources, prompts; JSON-RPC transport; capability discovery).
- No USB-C analogy, no "In today's rapidly evolving" opening.
- One runnable or traceable example (config snippet, session transcript,
  or protocol exchange).

## Sources

No supplied material. Primary sources expected (MCP specification,
official docs).

## Hard requirements

- States what problem MCP removes that REST/OpenAPI does not.
- Describes the host/client/server split correctly.
- Contains at least two checkable technical claims tied to sources.
